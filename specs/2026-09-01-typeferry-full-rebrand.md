# TypeFerry Full Rebrand Specification

## Problem

The monorepo, its three language implementations, protocol, public APIs, release automation, templates, and historical records are branded Bifrost. The chosen replacement is TypeFerry. The rename must be a clean break rather than a compatibility migration, while final external registry identifiers remain undecided.

## Evidence

- The clean save point `e08874ee9fe432b372d66f395e448c69ed24351b` is pushed and verified on the untouched Forgejo Bifrost repository.
- The local repository has no remaining Git remotes.
- 292 tracked files contain `Bifrost`, `bifrost`, or `BIFROST`.
- 428 tracked paths contain `bifrost` because the three implementation roots and many Rust crates/modules are branded.
- Brand identifiers are embedded in public TypeScript types, Python modules, Rust crates, WebSocket paths, Redis keys, room names, conformance fixtures, package metadata, CI, templates, specs, and decisions.

## Desired Outcome

Produce a repository whose active and historical tracked state consistently uses TypeFerry:

- root implementation directories become `typeferry-ts`, `typeferry-py`, and `typeferry-rs`;
- TypeScript public `Bifrost*` APIs become `TypeFerry*` with no aliases;
- Python imports move from `bifrost` to `typeferry`;
- Rust crates and crate imports move from `bifrost*` to `typeferry*`;
- protocol branding and wire identifiers become TypeFerry, including WebSocket paths, Redis keys, room names, constants, and fixtures;
- templates, CI, scripts, release documentation, specs, and decisions use TypeFerry throughout;
- historical filenames and narrative wording are rewritten rather than preserved;
- package manifests use temporary non-publishable local identities;
- publishing and automated release-bump workflows are disabled until registry identifiers are explicitly selected;
- the final local repository directory is `<user-home>/Repositories/example-app/typeferry`.

## Uncertainty

- External consumers of the already-published Bifrost packages will not be migrated by this repository-only operation.
- The untouched Forgejo Bifrost repository remains the recovery snapshot and will not receive TypeFerry commits.
- Final npm, PyPI, Cargo, and repository URLs are intentionally unresolved.
- The clean wire rename makes TypeFerry incompatible with existing Bifrost clients and servers by design.

## Contracts

### Naming mapping

Apply the semantic mapping consistently in tracked paths and text:

- `Bifrost` → `TypeFerry`
- `bifrost` → `typeferry`
- `BIFROST` → `TYPEFERRY`

Generated dependency metadata must be regenerated by its native package manager rather than trusted after textual replacement.

### Temporary package identities

- TypeScript package: `typeferry-ts`, marked private, with public-registry publishing configuration removed.
- Python distribution: `typeferry-py`, Python import package `typeferry`, with publishing automation disabled.
- Rust crates: `typeferry` and `typeferry-*`, with workspace publication disabled.
- Templates use repository-local TypeFerry dependencies where necessary for verification and clearly document that registry identifiers are pending.

### Public API and protocol

- No deprecated Bifrost API aliases remain.
- All public symbols, filenames, environment variables, error names, storage keys, room names, user agents, and display strings adopt TypeFerry.
- `PROTOCOL.md` remains normative and changes in the same implementation commit as wire constants and conformance fixtures.
- Protocol revision/version is incremented to reflect the breaking wire rename.

### Git and external-state boundary

- The existing Forgejo repository remains untouched after save-point verification.
- No new remote is created.
- Commits remain local and path-limited.
- The local top-level directory is renamed only after all repository-relative verification and commits complete.

## Test Strategy and Acceptance Criteria

Testing begins with baseline execution before implementation, followed by focused rename guards and full suites.

1. Record baseline results for TypeScript, Python, Rust, release-script, and template tests before the rename.
2. Add or update contract tests first where branded public/wire values have explicit assertions.
3. `git ls-files | rg -i 'bifrost'` returns no tracked paths.
4. `git grep -I -i 'bifrost'` returns no tracked content.
5. TypeScript lint, typecheck, split test runners, build, and dry-run pack pass from `typeferry-ts` using exact Node.js `24.19.0` and npm `11.17.0`.
6. Python formatting/static checks available in the project and the complete pytest suite pass from `typeferry-py`.
7. Rust formatting, clippy, and complete workspace tests pass from `typeferry-rs`.
8. Shared cross-language conformance tests pass with renamed paths and wire identifiers.
9. Version-bump/release helper tests pass or are replaced by explicit tests proving publication is disabled.
10. Template typecheck/tests/build pass using its temporary local TypeFerry dependency arrangement.
11. Manifests and packed artifacts expose only temporary non-publishable TypeFerry identities.
12. Publishing workflows are absent or inert and cannot publish temporary identities on push.
13. Git diff checks pass, all task-owned work is committed semantically, and the final directory is `<user-home>/Repositories/example-app/typeferry`.

## Risks and Mitigations

- **Partial rename:** use case-insensitive tracked-path and tracked-content guards after every unit.
- **Broken lockfiles:** regenerate npm and Cargo locks with native tools; verify Python packaging metadata through builds/tests.
- **Protocol drift:** update normative protocol, all implementations, and fixtures together; run cross-language conformance.
- **Accidental publication:** mark manifests private/non-publishable and remove or inert publishing workflows before committing implementation.
- **Historical link breakage:** rewrite all historical filenames and internal references consistently, then scan the complete tracked tree.
- **Filesystem/path disruption:** rename the repository root last, after commits and verification, and report the new absolute path.

## Recovery

- Before the root-directory rename, revert local TypeFerry commits to restore the Bifrost working tree.
- After the root-directory rename, rename the directory back and revert the local commits if required.
- The untouched Forgejo `main` at `e08874e` is the authoritative remote recovery point.
- No registry packages, Forgejo repositories, or persisted external data are modified by the rename.
